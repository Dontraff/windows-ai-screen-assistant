# Windows AI Screen Assistant

WPF-приложение для периодического анализа выбранного монитора через AI Tunnel. Интервал по умолчанию — 120 секунд, длительность тренировки — 50 минут.

## Сборка и запуск

Нужна Windows 10 версии 2004 (сборка 19041) или новее, включая Windows 11, и [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0). Для запуска framework-dependent сборки нужен **.NET Desktop Runtime 8**. На компьютере с SDK той же архитектуры он уже установлен. Windows Graphics Capture требует интерактивного рабочего стола и проверяется при открытии системного выбора.

В **Visual Studio 2022 17.8+** установите рабочую нагрузку «Разработка классических приложений .NET», откройте `ScreenAssistant.sln`, выберите `ScreenAssistant` запускаемым проектом и нажмите F5. В VS Code откройте папку проекта и выполните в PowerShell:

```powershell
dotnet restore .\ScreenAssistant.sln
dotnet build .\ScreenAssistant.sln -c Release --no-restore
dotnet test .\ScreenAssistant.sln -c Release --no-build
dotnet run --project .\src\ScreenAssistant\ScreenAssistant.csproj -c Release --no-build
```

Автономная сборка для переноса на Windows x64 включает .NET Desktop Runtime:

```powershell
dotnet publish .\src\ScreenAssistant\ScreenAssistant.csproj -c Release -r win-x64 --self-contained true -o .\publish\win-x64-panel
```

Запустите `ScreenAssistant.exe` из папки публикации. Для Windows на ARM укажите `win-arm64`. Папку публикации переносите целиком.

## Первый запуск

1. Нажмите **Выбрать…** и в системном окне укажите нужный монитор. Системный диалог Windows также может предлагать захват окна.
2. Нажмите **Снять кадр**, чтобы проверить предпросмотр. Эта кнопка работает локально.
3. Оставьте Base URL `https://api.aitunnel.ru/v1` или укажите HTTPS-адрес совместимого API, включая путь к версии. Вставьте API-ключ. Кнопка **Каталог** загружает публичный каталог AI Tunnel и предлагает модели, принимающие изображения и выдающие текст. ID также можно ввести вручную, например для другого совместимого API.
4. При необходимости нажмите **Сохранить настройки**. Ключ хранится для конкретного Base URL и профиля Windows. Чтобы удалить сохранённый ключ для текущего адреса, очистите поле и снова сохраните настройки.
5. Нажмите **Запустить**. Сначала приложение просит модель распознать цвета на синтетической картинке. Такой запрос может тарифицироваться. После успешной проверки начинается отсчёт тренировки и сразу снимается первый кадр. Во время захвата горит индикатор. Статус API, счётчики и остановка доступны в нижней панели.
6. Откройте **История**, чтобы выбрать предыдущий ответ текущей сессии. Счётчик «Запросы кадров» включает неуспешные попытки анализа кадра. Проверка модели и загрузка каталога считаются отдельно от кадров и в этот счётчик не входят.

Снимки выбранного источника отправляются на настроенный HTTPS-адрес. При захвате всего монитора видимые на нём окна, включая окно самого ассистента, попадают в кадр. Windows может ограничивать захват защищённых окон, заблокированного рабочего стола и отдельных удалённых сессий. При закрытии источника или его недоступности снова выберите монитор.

## Плавающее окно

- Включите **Плавающий ответ** в верхней панели главного окна. Компактная строка откроется поверх обычных окон. Она показывает проверку модели, загрузку, текст ответа и ошибки.
- Во вкладке **Оверлей** главного окна можно выбрать компактный или многострочный режим, ширину, высоту, размер шрифта и непрозрачность фона. Перетащите окно за верхнюю панель: за строку ответа в компактном режиме или за строку статуса в многострочном. Кнопка **Сбросить положение** возвращает окно в верхнюю правую часть монитора главного окна. При непрозрачности 0% обе заливки прозрачны. Для перемещения нажмите на видимый текст. Компактный режим показывает только первую строку ответа модели. Если она длинная, строка заканчивается многоточием. Полный текст доступен во вкладке **Последний ответ**.
- Переключатель **Плавающий ответ** в главном окне отключает оверлей. Его можно снова включить в главном окне, в том числе во время анализа. Положение, вид и состояние переключателя сохраняются в `%LOCALAPPDATA%\ScreenAssistant\overlay.json`.
- **Потоковые ответы** включены по умолчанию. При поддержке SSE текст появляется по мере генерации. Если совместимый сервер отклоняет параметр `stream`, остановите тренировку, выключите этот режим и запустите её снова. Ответ в формате JSON отображается целиком.
- При захвате монитора оверлей попадает в кадр, если он расположен на этом мониторе. Остановка тренировки оставляет последний полный ответ доступным для чтения.

## Настройки и данные

Образец — [settings.example.json](settings.example.json). Его можно скопировать в `%LOCALAPPDATA%\ScreenAssistant\settings.json` перед запуском или задать параметры через интерфейс.

- `settings.json` хранит Base URL, ID модели, интервал (5–3600 секунд), длительность (1–720 минут) и настройку пропуска одинаковых кадров.
- Файлы `key-*.dpapi` содержат зашифрованные ключи текущего пользователя Windows. Приложение подставляет ключ для текущего Base URL и отключает HTTP-перенаправления.
- `errors.log` содержит время, этап, тип ошибки, HRESULT и HTTP-статус, если он доступен. Сохраняется один предыдущий журнал. Тела запросов и ответов, ключи и изображения в журнал не записываются.
- В оперативной памяти остаются текущий предпросмотр и до 200 ответов. История сбрасывается при начале новой тренировки после успешной проверки модели.

## Структура

```text
ScreenAssistant.sln
settings.example.json
src/
  ScreenAssistant/
    ScreenAssistant.csproj
    app.manifest
    App.xaml, App.xaml.cs
    MainWindow.xaml, MainWindow.xaml.cs
    Overlay/OverlayWindow.xaml, OverlayWindow.xaml.cs, OverlayViewModel.cs
    Overlay/OverlayPreferences.cs, WpfOverlayRenderer.cs
    Configuration/UserSettings.cs
    ScreenCapture/D3DDevice.cs
    ScreenCapture/GraphicsCapture.cs
    ScreenCapture/FrameEncoding.cs
  ScreenAssistant.Core/
    ScreenAssistant.Core.csproj
    AIClient/AiClient.cs, ResponseParser.cs
    Overlay/IOverlayService.cs, OverlayManager.cs
    Scheduler/AnalysisScheduler.cs
tests/
  ScreenAssistant.Tests/
    ScreenAssistant.Tests.csproj
    AiClientTests.cs
    AnalysisSchedulerTests.cs
    OverlayManagerTests.cs
```

- **ScreenCapture** связывает системный picker с HWND WPF и запускает короткую D3D11-сессию на каждый снимок. Кадр копируется в `SoftwareBitmap` и кодируется в памяти. При изменении размеров во время захвата пул создаёт буферы нового размера. Захват использует реальные пиксели, а интерфейс объявляет Per-Monitor V2 DPI. Windows управляет стандартной рамкой захвата. Курсор исключён из кадра, чтобы его движение не мешало сравнению.
- **FrameEncoding** сохраняет пропорции и уменьшает длинную сторону до 2560 пикселей. PNG сохраняет мелкий текст без артефактов сжатия. Если PNG занимает больше 4 МиБ, приложение использует JPEG с качеством 90. Сравнение идёт по SHA-256 от PNG после масштабирования. Даже небольшое изменение, например часы на панели задач, может вызвать новый запрос. После ошибки тот же кадр остаётся доступен для анализа на следующем шаге.
- **AIClient** повторно использует один `HttpClient` и отправляет `image_url` с PNG/JPEG data URI в `chat/completions`. Тайм-аут API — 60 секунд. Для модели требуется поддержка изображения на входе и обычного текстового ответа в `choices[0].message.content`. Если конкретный ID, пресет или формат ответа несовместим, выберите модель из каталога и повторите запуск.
- **Scheduler** отсчитывает интервал между началами анализов, ожидает завершения текущей операции и отменяет её при остановке или истечении времени. Автоматических повторов внутри запроса нет. При временной ошибке следующий цикл учитывает `Retry-After`, а при HTTP 429 без этого заголовка действует пауза от 30 секунд. Ошибки параметров, ключа, доступа и оплаты завершают тренировку.
- **OverlayManager** получает статусы и части ответа через `IOverlayService`. `ResponseParser` читает SSE, а менеджер принимает обновления только для активного запроса и передаёт их в WPF через Dispatcher. `OverlayViewModel` связывает текст, статус и настройки с окном. Компоненты создаются и связываются в `App.OnStartup`.
- **Тесты** используют подменный HTTP-обработчик и управляемые часы. Реальный ключ для них не нужен. Для ручной проверки Windows выберите монитор, получите локальный кадр, затем запустите тренировку с действующим ключом. Проверьте ответ, историю, остановку и повторный выбор источника.

## Проверка оверлея

Для ручной проверки оверлея включите **Плавающий ответ**, запустите тренировку и убедитесь, что текст появляется до окончания генерации. Закройте и снова откройте окно во время ответа. Проверьте перенос на другой монитор, изменение вида и восстановление положения после перезапуска. После остановки последующий фрагмент отменённого запроса не должен менять ответ.
